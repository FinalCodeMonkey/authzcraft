# RBAC 前端验收清单

> 本清单用于验收按 `rbac-system-builder` 生成或改造的 RBAC 前端管理页。验收目标是确认页面真实可用、后端权限真实生效、AuthzCraft 回路 2 数据权限配置可闭环，而不是只检查页面是否能打开。

## 一、验收前提

- 已确认目标前端工程、路由入口、API 客户端、组件库和登录态来源。
- 已读取 `frontend-rbac-page-spec.md`、`authzcraft-rbac-api-contract.md`、`data-permission-template-ast-spec.md`。
- 已确认接口真实可用；如接口缺失，必须输出缺口清单，不得用 mock-only 页面宣称完成。
- 已准备至少 3 类测试主体：管理员、普通用户、无权限用户。
- 已准备至少 1 个数据表，包含本人字段和部门字段。

## 二、角色与用户组管理

| 验收项 | 必须满足 |
|---|---|
| 角色列表 | 支持分页、搜索、状态筛选；展示角色编码、名称、状态、成员数、权限数、更新时间 |
| 创建/编辑角色 | 真实调用 AuthzCraft 角色接口或业务侧代理接口；保存后列表和详情回显一致 |
| 删除/退休角色 | 展示成员数、功能权限数、字段权限数、数据权限数；二次确认后才提交 |
| 用户组列表 | 支持分页、搜索、状态筛选；展示用户组编码、名称、状态、成员数、关联角色数 |
| 创建/编辑用户组 | 真实调用 AuthzCraft 用户组接口或业务侧代理接口；保存后列表和详情回显一致 |
| 删除/退休用户组 | 展示成员和授权影响范围；二次确认后才提交 |
| 默认权限 | 新建角色、用户组默认不授予高风险权限 |

## 三、双向批量成员分配

| 验收项 | 必须满足 |
|---|---|
| 人员维度分配 | 选择一个或多个人员后，可一次分配多个角色或用户组 |
| 角色/用户组维度分配 | 进入角色或用户组后，可批量添加或移除人员 |
| 搜索与筛选 | 支持按关键词、部门、岗位筛选人员；支持角色/用户组搜索 |
| 跨页选择 | 分页切换后已选对象不丢失 |
| 去重 | 已有关联必须标记；重复分配不生成重复成员关系 |
| 变更预览 | 保存前展示新增、保留、移除、重复、冲突和无效项数量 |
| 保存反馈 | 保存后展示成功数、失败数和失败明细，失败项可定位到具体人员和目标角色/用户组 |
| 高风险操作 | 清空成员、批量移除成员必须二次确认并展示影响范围 |

## 四、功能授权

| 验收项 | 必须满足 |
|---|---|
| 授权形态 | 使用资源树、树表或权限矩阵，不使用难以扫描的平铺长列表作为唯一入口 |
| 权限分组 | 按应用、模块、页面、按钮/API、字段分组展示 |
| 编码一致 | 前端 `permissionCode` 与后端拦截器、DDL 或权限表逐字一致 |
| 半选态 | 父子权限支持全选、半选、取消选择 |
| 搜索过滤 | 支持按权限名称、编码、模块搜索定位 |
| 只看已授权 | 支持只看已授权和只看变更 |
| 高风险标识 | 删除、导出、批量操作等高风险权限有明显标识 |
| 保存预览 | 保存前展示新增、移除、保留权限差异 |
| 运行时生效 | 授权后菜单/按钮/API 可访问；取消授权后菜单/按钮隐藏，直接请求后端返回 403 |

## 五、字段权限

| 验收项 | 必须满足 |
|---|---|
| 权限级别 | 两维模型：`security_requirement`（字段固有属性，PLAIN/MASKED/HIDDEN）× `access_level`（授权可变，NONE/READ/PLAIN_READ/WRITE） |
| 表分组 | 字段按数据表分组（折叠面板），展示字段中文名、字段编码、安全要求标签（HIDDEN 红/MASKED 橙/PLAIN 绿）、当前授权目标访问级别（单选组，含"无权限"档） |
| 授权目标过滤 | 字段权限 tab 只显示当前角色/用户组/人员已绑定或本次待保存绑定的字段，不显示全局所有字段定义；切换授权目标后列表随绑定集合切换 |
| 未选目标状态 | 未选择授权目标时字段权限列表为空，保存按钮置灰；功能权限可显示全部权限项但不勾选，数据权限不显示全局规则 |
| 添加已有字段 | 空列表角色/用户组点击“添加字段”选择已存在字段定义时，后端不重复插入定义，前端立即显示该字段并启用保存；保存后刷新/切换回来仍只显示该目标绑定字段 |
| 显式 NONE | `NONE` 是可保存的显式 access_level；绑定 `NONE` 后字段运行时完全不返回。删除绑定只表示回退默认访问级别，不能当作无权限 |
| 编辑/删除定义 | 编辑字段只改字段业务名等展示信息，安全要求只读；删除字段定义会全局删除该字段全部 option，并清理角色/用户组绑定，必须危险按钮二次确认 |
| 字段名称 | `name` 只存字段业务名（如"报销金额"），不拼接访问级别后缀（如"报销金额可读"） |
| 批量设置 | 支持对同一资源下多个字段批量设置权限 |
| 后端执行 | 读接口真实隐藏或脱敏无权字段；写接口拒绝或剔除无写权限字段 |
| 配置化驱动 | 业务查询 SQL 查出全部字段（`SELECT *`），字段投影从 AuthzCraft 字段目录 `security_requirement` 配置驱动，不硬编码受控字段列表 |
| 无绑定默认处理 | 用户无字段权限绑定时，`HIDDEN` 字段移除、`MASKED` 字段脱敏 `***`、`PLAIN` 字段原样返回——不得跳过 |
| 全表覆盖 | 所有业务查询接口统一经过字段投影（`projectRows`），不得只给个别表加字段权限 |
| 绕过验证 | 直接构造请求提交无权字段不能写入成功 |
| 前端边界 | 前端只做显示、只读、脱敏提示和提交前剔除，不作为安全边界 |

## 六、五项可见数据范围模板

### 0. 数据权限列表

| 验收项 | 必须满足 |
|---|---|
| 列定义 | 授权目标类型、授权目标、数据表（授权目标视角）、数据规则名称、数据规则模板、状态、操作；**不展示**"规则摘要""失效时间"等冗余列 |
| 数据规则模板来源 | 取自策略 ACTIVE 修订关联的**规则蓝图 `display_name`**（后端 `ruleBlueprintDisplayName`），不得前端硬编码或解析 displayName |
| 按授权目标过滤 | 选中右上角授权目标后，列表只显示该主体的规则；未选时显示全部供浏览 |
| 状态 | 展示"生效/已禁用/已作废"，随授权 `lifecycleState` 变化 |
| 操作 | 修改/禁用/作废按钮随状态显隐；作废不可逆需二次确认 |

### 0.1 配置表单 input_schema 动态渲染

| 验收项 | 必须满足 |
|---|---|
| 蓝图 schema 查询 | 前端 onMounted 时从 PAP `POST /policies/rule-blueprints/search` 查询蓝图 `input_schema`，缓存到 `blueprintSchemas` |
| 字段动态显示 | 切换"可见数据范围"模板时，表单字段根据当前模板的 `input_schema` 动态显示/隐藏：`fieldInputs` 有 `anchorField` 时显示"数据归属字段来源"+"数据归属字段"；`argumentInputs` 有 `departmentScopes` 时显示"部门范围"；有 `specifiedDepartmentCodes` 时显示"指定部门"；有 `sharedOwnerUserKey` 时显示"数据归属人"；有 `allowReshare` 时显示"允许再次分享" |
| ALL_DATA 无字段 | `ALL_DATA` 模板（`STANDARD_BLUEPRINT`，`input_schema` 为 `{}`）不显示数据归属字段和参数输入控件 |
| PAP 离线降级 | PAP 不可用时前端回退为不显示额外配置字段（不阻塞基础表单） |

### 1. 页面术语

| 验收项 | 必须满足 |
|---|---|
| 主标签 | 使用“授权目标类型”“授权目标”“数据表”“可见数据范围”“规则模板”“数据归属字段来源”“关联表”“数据归属字段”“失效时间” |
| 来源选项 | 数据归属字段来源只展示“本表”“关联表” |
| 禁用旧词 | 不以“授权主体类型”“授权对象”“业务资源”“数据权限模板”“锚点位置”“锚点字段”“关联资源”作为主配置表单标签 |
| 测试字段 | “保存后验证访问人”不得出现在主配置表单；如提供测试入口，独立区域字段名使用“测试人员” |
| 技术键 | `resourceKey`、`fieldKey`、`accessPathKey`、`operationCode` 只能作为辅助信息或内部字段，不能作为主要选项文案 |
| 标签有效性 | 控件选项、分组标题或页面标题已经表达含义时，不再显示重复 label；`角色/用户组/人员` 前不再放 `授权目标类型`，`本表/关联表` 前不再放重复解释，`我的数据/我管理部门的数据/指定部门数据` 前不再重复同义标题 |
| 辅助说明 | 只用于说明约束、风险、示例或业务后果，不用于复述控件文字 |

### 0-A. 全部数据

| 验收项 | 必须满足 |
|---|---|
| 简单配置 | 业务人员只需选择授权目标、数据表、操作范围；无需数据归属字段、部门范围、归属人等参数 |
| 隐藏参数 | 选择全部数据后，前端隐藏数据归属字段来源、关联表、数据归属字段等配置项 |
| AST 编译 | 后端编译为 `{"operator":"TRUE"}` 谓词，`templateBinding.conditions` 为空数组 |
| simulation | simulation 期望 `ALLOW_ALL`（而非其它模板的 `FILTER`） |
| 冲突提示 | 全部数据覆盖同主体同资源的其它规则时，保存前弹窗提示“该规则将覆盖同主体的其它数据范围规则” |
| 业务回显 | 回显“允许某授权目标访问某数据表的全部数据”类摘要 |

### 1. 我的数据

| 验收项 | 必须满足 |
|---|---|
| 简单配置 | 业务人员只需选择授权目标、数据表、操作范围、数据归属字段 |
| 默认推荐 | 默认推荐负责人、创建人、销售、申请人等候选数据归属字段 |
| AST 编译 | 后端生成 `EQ(fieldKey, currentUserId)` 类型 Predicate AST |
| 授权绑定 | 授权绑定到所选角色、用户组或人员 |
| simulation | 启用前 simulation 通过；失败时不激活并展示 explain 摘要 |
| 业务回显 | 回显“允许某授权目标访问某数据表中某字段是本人的数据”类摘要 |

### 1-A. 关联字段锚点

| 验收项 | 必须满足 |
|---|---|
| 关联表选择 | 选择根资源后，可选择以该资源为 root 的 ACTIVE access path 所指向的关联表；页面主选项展示表业务名称，不展示 path key 作为主要文案 |
| 目标字段 | 选择关联表后，数据归属字段列表来自该表对应 destination 资源的可过滤字段 |
| AST 编译 | 后端生成 `EXISTS_PATH(accessPathKey, pathPredicate)`，其中 `pathPredicate` 使用目标资源字段 |
| PEP 映射 | 业务侧 PEP 配置存在同名 access path 映射，运行时 SQL 编译为参数化 `EXISTS` 子查询 |
| 典型场景 | `WB_MEETING` 可通过 `WB_MEETING_TO_PARTICIPANT.participant_user_id = currentUserId` 表达“我参与的会议” |
| 缺口处理 | access path 未登记、root 不匹配、目标字段不可过滤或 PEP 映射缺失时，必须提示缺口，不得保存为伪完成 |

### 2. 我管理部门的数据

| 验收项 | 必须满足 |
|---|---|
| 范围复选 | 支持直接管理部门、管理的下级部门、分管的部门多选 |
| 下级层级 | 勾选管理的下级部门后，可选择 1 级、2 级、3 级或全部下级 |
| 默认值 | 默认勾选直接管理部门，避免空配置 |
| AST 编译 | 后端生成 `IN(departmentAnchorField, managedDepartmentCodes)` 类型 Predicate AST |
| PIP 参数 | `MANAGED_DEPARTMENT_CODES` 能消费 `departmentScopes` 和 `subDepartmentDepth` |
| 缺口处理 | 若 PIP 不支持范围/层级参数，必须输出缺口清单，不得宣称完成 |
| simulation | 正向和反向断言通过后才可启用 |

### 3. 指定部门数据

| 验收项 | 必须满足 |
|---|---|
| 多选部门 | 支持一次指定一个或多个部门编码，不依赖管理层级 |
| 必填校验 | 未指定任何部门时不允许保存 |
| AST 编译 | 后端生成 `IN(departmentAnchorField, specifiedDepartmentCodes)` 类型 Predicate AST，右值为授权参数而非请求属性 |
| 与模板 2 区分 | 不调用 `MANAGED_DEPARTMENT_CODES` 解析器，部门编码直接作为授权参数落地，不随请求人的管理关系变化 |
| simulation | 命中指定部门编码集合中任一项应产生 `FILTER`；不在集合中的数据不应被允许 |
| 业务回显 | 回显“允许某授权目标访问某数据表中某字段属于指定部门（...）的数据”类摘要 |

### 4. 分享某人的数据权限给某人

| 验收项 | 必须满足 |
|---|---|
| 简单配置 | 业务人员选择数据归属人、被分享人、数据表、操作范围和有效期 |
| 无隐藏默认值 | 数据归属人字段初始为空，不得预置任何真实用户/角色编码作为默认值；未选择时阻止保存并提示 |
| 主体语义 | 授权绑定主体是被分享人/角色/用户组，不是数据归属人 |
| AST 编译 | 后端生成 `EQ(ownerAnchorField, sharedOwnerUserKey)` 类型 Predicate AST |
| 授权参数 | `sharedOwnerUserKey` 写入授权参数，不写死在前端过滤逻辑中 |
| 撤销能力 | 支持查看分享记录和撤销分享 |
| 有效期 | 默认要求有效期或提供明确撤销入口 |
| simulation | 被分享主体访问归属人数据通过；非被分享主体或其他归属人数据不通过 |

### 5. 部门范围参数化验收（回接 AuthzCraft PIP）

| 验收项 | 必须满足 |
|---|---|
| DIRECT_MANAGED | 保存 `departmentScopes=["DIRECT_MANAGED"]` 后，PIP 解析出的 `managedDepartmentCodes` 只含直接管理部门（闭包 `depth = 0`） |
| SUB_MANAGED 层级 | `subDepartmentDepth=1/2/3/ALL` 的解析数量应随层级递增，验证闭包 `depth` 上限生效；验收断言必须验证 `0 < direct < subAll` 这类数量差异，不能只检查非空 |
| PORTION_MANAGED | 保存 `departmentScopes=["PORTION_MANAGED"]` 后，PIP 按 `portion_manage_user_id` 解析分管部门 |
| 端到端 | 五项通用模板保存均返回 `code=0` 且 simulation 通过；中心 plans 的 binding 数量随范围变化 |
| 仓储层单测 | `JdbcPrincipalAttributeRepositoryTest` 必须覆盖 `DIRECT_MANAGED`、`SUB_MANAGED depth=1/ALL`、`PORTION_MANAGED`、空 scope/`ALL_MANAGED` 回退，验证闭包表与分管字段的 SQL 行为 |

## 七、权限运行时与回路协同

| 验收项 | 必须满足 |
|---|---|
| 无认证 | 未登录访问受保护 API 返回 401 |
| 无认证响应体 | 401 响应包含统一错误结构、稳定错误码和可读 message，不得只有空 body |
| 无功能权限 | 已登录但无功能权限返回 403，且不触发业务查询和数据 PEP |
| 无功能权限响应体 | 403 响应包含统一错误结构、稳定错误码和可读 message，且不返回回路 2 `decisionKey` |
| 有功能无数据 | 有功能权限但无数据授权时，由回路 2 返回空集、拒绝或受控过滤结果 |
| requestKey | 回路 1 鉴权记录与回路 2 `decisionKey` 可通过同一 `requestKey` 串联 |
| 前端不行过滤 | 前端不根据角色、部门、用户 ID 过滤业务行数据 |
| 字段权限 | 前端字段控制来源于后端 `fieldPermissions`，后端仍真实执行字段过滤/拒绝 |

## 八、接口与缺口处理

| 验收项 | 必须满足 |
|---|---|
| API 契约 | 前端 API client 字段与 `authzcraft-rbac-api-contract.md` 对齐，差异通过 adapter 处理 |
| 接口缺失 | 输出缺口清单，包含缺失 API、使用页面、阻塞程度、请求/响应字段草案 |
| mock 限制 | mock 只能用于临时开发，不得作为最终验收依据 |
| 错误展示 | 接口失败时保留用户已填内容，展示可理解错误信息 |
| 部分成功 | 批量接口部分成功时展示成功数、失败数和失败明细 |

## 九、前端工程质量

| 验收项 | 必须满足 |
|---|---|
| 长 ID | 所有 ID 类型为 `string`，禁止 `Number()`、`parseInt()`、一元 `+` |
| 权限来源 | 菜单、按钮、字段交互只基于当前用户权限接口返回值 |
| 路由保护 | 无权限路由不可访问，直接输入 URL 显示 403 或无权限页 |
| 状态覆盖 | 加载中、空数据、无权限、保存中、保存成功、部分成功、接口失败、只读模式均有处理 |
| 组件复用 | 批量选择、变更预览、确认弹窗应复用项目既有组件或形成稳定本地组件 |
| 无第二身份源 | 不新增独立登录、用户表或组织表作为权限管理的数据源 |

## 十、完成判定

只有同时满足以下条件，才能声明 RBAC 前端管理页完成：

1. 所有页面真实调用后端或 AuthzCraft 接口。
2. 角色、用户组、成员、功能授权、字段授权、数据权限六类能力均可操作。
3. 五项可见数据范围模板能生成 AST、绑定授权、通过 simulation 并可查询/审计；关联表字段场景必须生成并执行 `EXISTS_PATH`。
4. 功能权限、字段权限、数据权限均由后端真实执行。
